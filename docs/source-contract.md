# 实验室及项目档案台协议

页面 / 是实验室任务列表，/report?id=R-A 展示正式报告元数据与带摘要的原件链接。初始R-A签发延迟项目，R-J为功耗/温度联合报告，PRE仅预览；同样品、驱动与固件组合组成独立配置。下载文件均是合成仪器二进制字节，文件展示名可能相同，以报告清单中的原始name区分。
页面 /archive 是独立项目档案台。先经文件选择控件上传原件并填写清单文件名，再填写移交引用key、报告号、项目范围。上传后的摘要由接收端返回；联合项目不允许拆开，未签发或原件不足拒收。key表示一次移交意图，同key查询/重交返回同一收件记录。/history 展示逐项归档号与pending，不等同整个样品归档完成。
本地控制retest签发R-B，只替代R-A:latency；revoke撤签R-A而不撤销联合报告。R-C提供两个可独立引用项目bandwidth/stability。partial令下一独立移交只接收首项，complete恢复接收；lose_reply在来源写入归档记录后向页面返回503，历史仍可核实。业务通过Chromium领取、上传与读回执，不能用演练控制替实验室签发。

本地来源控制通过 POST /__control 发送JSON，例如 {"event":"reset"} 可重置样本。控制切换只影响合成来源，不能用来替业务处理方决定批准、签发或确认。来源服务与自动化客户端分别承担各自责任。
